# ROOM PILOT UIモック生成プロンプト集（画像生成AI用）

生成AIに画面カンプを描かせるためのプロンプト。**「共通仕様」を毎回先頭に貼り、その後ろに画面ごとのブロックを1つだけ足して1枚ずつ生成する**。同じ会話で続けて依頼するとトーンが揃いやすい。

---

## 0. 共通仕様（毎回、先頭に貼る）

```
モバイルアプリのUIデザインカンプを1枚作ってください。実機スクリーンショット風に、画面そのものを正面から描いてください。端末フレーム、手、机、パース、反射、装飾的な影は描かないこと。

■ 前提
- プロダクト名：ROOM PILOT（賃貸不動産の営業担当者が使う業務アプリ。LINEの中で開く）
- 利用者：営業担当者。外出先で片手で操作する。
- 画面比率：縦長 9:19.5（iPhone相当）。幅390px相当のレイアウトとして設計すること。
- 言語：すべて日本語。以下で指定した文字列だけを、そのまま正確に描画すること。指定していない文字・英単語・ダミーテキストを勝手に足さないこと。

■ デザインシステム（厳守）
- 背景 #F6F5F2 ／ カード #FFFFFF ／ 本文 #202225 ／ 補助文字 #6B6B6B
- アクセント：ウォームオレンジ #F3A36F。主要ボタン・現在地・強調だけに使い、多用しない。
- 状態色：空室/完了=グリーン #3E8E5A、期限注意=アンバー #C98A20、募集終了/期限超過=レッド #C2564B、未確認/情報不足=グレー #9A9A9A
- 角丸：カード24px、ボタン16px、バッジは完全なピル型
- 余白：画面左右16px、カード内padding16px、カード間12px
- 文字：Noto Sans JP。見出しは太字、本文はレギュラー。装飾フォントや手書き風は使わない。
- タップ領域は最小44px四方。屋外で読むため、薄すぎる文字色や低コントラストの装飾は使わない。
- 影は黒4%程度のごく弱いものだけ。グラデーション、グラスモーフィズム、イラスト、写真加工、3Dは使わない。

■ 固定フッター（全画面共通・画面下端に固定）
左から「顧客」「物件」「今日」「内見」「案件」の5項目。中央の「今日」だけ円形ボタンとして一段高く浮き、淡いオレンジのグローを持つ。現在地の項目はアイコンと文字の両方を濃くして示す。
フッターの上には必ず十分な余白を取り、コンテンツやボタンがフッターに重なったり、見切れたりしないこと。

■ 禁止
- 氏名とステータスを同じ行に詰めないこと。人物名は必ず独立した行に置き、ステータスや時刻は次の行に分ける。
- 文字を潰さない。読めない小さな文字列を並べない。
```

## 3. 物件（候補の仕分けデッキ）

> この画面だけは**ダーク**で、共通仕様の配色を次のとおり読み替える。実装（`public/app.js` / `styles.css`）もこの形になっている。

```

この画面は、営業が候補物件を1枚ずつ見比べるカードデッキ。カードは画面のほぼ全面を占め、面いっぱいに室内写真を敷く。

**この画面には5タブの固定フッターを描かないこと。**画面を広く使うため、移動導線は右下の丸ボタンに集約している。

上から順に：
1. 画面上部に細いバー。左に小さなオレンジの丸、その右に小さく「この顧客に提案」と太字「藤田 さくら」、右端に小さなボタン「変更」。

   カード面いっぱいに明るいリビングの写真。上下に黒のグラデーションを重ねて文字を読ませる。
```

## 7. 使うときのコツ

- **1枚ずつ生成する。** 5画面を一度に頼むと、どの画面も情報が間引かれる。
- **現状のスクリーンショットを参照画像として添付する。** 文章だけより一貫性が上がる。「この配色と余白を保ったまま、レイアウトだけ改善して」と添えると、既存の実装からの差分として読める。
- **日本語の描画は崩れることがある。** 崩れた場合は「文字は指定した文字列を正確に描くこと。読めない文字を並べないこと」を再度添えて作り直す。それでも崩れるなら、**配置・階層・余白を見るための下絵**と割り切り、文字は実装側で入れる。
- **修正は差分で頼む。** 「3の注意バーだけ、アンバーから赤に変えて、他は完全に同じで」のように、変える箇所だけを指定する。
- 生成物は `docs/` ではなく `design-refs/` など別フォルダに置き、実装の正本（`docs/architecture.md`）と混ぜない。
